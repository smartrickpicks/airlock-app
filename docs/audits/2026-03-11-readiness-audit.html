Jane — Builder

Discover + Build chambers · Drafts and assembles vault content
Login & Onboarding
Partial ▶

EXISTS: OAuth2 Google Sign-In flow, dev login buttons, onboarding store with checklist tracking, 32KB setup wizard page.

MISSING: Real workspace creation (client-side mock only), email verification, team invitation during setup, module preference selection. First-time user detection is fragile (org_role === "member"). After login, route hardcoded to /contracts/triage regardless of role.

Dispatch (Homepage)
Partial ▶

EXISTS: Dispatch view (600+ lines), onboarding empty state, dynamic import of DispatchCharts, mock operator feed/signals/queue, notifications store, event feed.

MISSING: Triptych layout (Signal | Orchestrate | Control) — current layout is single full-width. Triage Signals widget not integrated. All charts/feeds pull from hardcoded mock data. No dynamic widget configuration.

Contract Intake + Extraction
Works ▶

EXISTS: Full intake lab with PDF upload → parse → preflight → extraction. Six real extractors (boolean, split, picklist, date, pattern, text). Confidence scoring per field. 50+ field extraction. Create vault from document. Card grid triage view with health scores.

GAPS: Uploaded document doesn't visually link to vault in downstream views. No field search/filter for 50+ fields. No bulk operations.

This is the strongest workflow in the platform.

Build Chamber (Field Editing)
Missing ▶

EXISTS: Patch route, patch store with full state management, patch model in DB, API routes for patch operations.

MISSING: No Build chamber view (/contracts/build/ doesn't exist). RecordInspector is read-only — no inline edit mode, no edit drawer, no field inputs. No patch creation workflow in the UI. No build progress metrics. No collaborative editing.

This is the #1 blocking gap. Builders can extract data but cannot edit it. The entire Build phase is unusable.

CRM Module
Partial ▶

EXISTS: Routes for accounts/contacts/activity. AccountsTable shows vault hierarchy as CRM. CRM store fetching from API. React Admin integration hinted (SSR disabled).

MISSING: Contacts and deals views empty. No entity linking to vaults. No bulk actions (merge, reassign). No activity timeline. Spec says vault hierarchy IS the CRM, but UI suggests separate system.

Triage (Tasks)
Partial ▶

EXISTS: Kanban board (TasksKanban), drag-drop, tasks store, backend service and routes. Routes for inbox/board/my-tasks/timeline.

MISSING: Triage Signals on Dispatch not integrated. Can't create tasks linked to vaults. No task templates. No cross-module assignment. No SLA visualization. Kanban is completely isolated from vault workflow.

Calendar Module
Stub ▶

EXISTS: Month/agenda routes, calendar store, backend service, FullCalendarView wrapper.

MISSING: No event creation. No vault deadline sync. No recurring events. No calendar integrations (Google, Outlook).

Documents Module
Stub ▶

EXISTS: Library route, documents store, backend service, document model in DB.

MISSING: No document search. No full-text retrieval UI. No folder hierarchy. No sharing/permissions. No versioning. No tagging. Documents uploaded during intake but can't browse them later.

Chat & Messenger UI
Backend Only ▶

EXISTS: Full backend chat service (conversations, messages, reactions, GIFs, read receipts, typing indicators). Messenger store (593 lines) with complete state management. WebSocket real-time delivery.

MISSING: No chat panel visible in any view. ConversationList/ChatView components exist but not wired to Dispatch or shell. No conversation drawer. No unread badge. No message search.

The backend is production-ready. The frontend just never connected it.

Jane's Day 1: "Extraction is impressive — I uploaded a contract and got 50+ fields extracted instantly. But then I couldn't edit any of them. No Build chamber, no chat to ask for help, no Otto to guide me. I'm stuck after step 3 of a 10-step workflow."

Tom — Gatekeeper

Review chamber · Reviews, approves, and rejects vaults and patches
Review Queue
Partial ▶

EXISTS: Review queue route + store + API. Vaults in Review chamber grouped by entity with health scores. Filterable by builder/entity.

MISSING: No notification when vaults enter Review. No priority ranking. No deadline/SLA indicators on queue items.

Patch Review System
Partial ▶

EXISTS: Complete patch state machine (draft → submitted → approved → applied). Self-approval properly blocked. Patch store, API routes, service layer.

MISSING: No diff view (can't compare original vs. proposed values). No batch approve/reject. No patch comments.

Vault Approval Flow
Missing ▶

CRITICAL: No formal approval model. Vaults can be advanced to Ship with just a role check — any Gatekeeper can click "Advance" without formal sign-off, owner approval, evidence pack review, or business rule validation.

chamber_rules.py defines check_review_to_ship() that validates gate status, entity resolution, and patch approvals — but the advance_chamber route never calls it.

Not safe for contracts worth real money.

Evidence Packs
Missing ▶

MISSING: No unified view bundling documents + extractions + patches for review. Gatekeepers see data in separate views but can't certify they've reviewed all supporting evidence for a contract.

Gate Response System
Missing ▶

EXISTS: Vault-level gate field in data model. ApprovalGate component. Playbook-level gate UI (DAG nodes).

MISSING: No vault-level gate response routes. Can't formally pass/fail/override a gate. No gate criteria configuration. Business rules written but not called.

Audit Trail
Works ▶

EXISTS: All vault operations logged as immutable events (who, when, what). AuditTrailPanel component. Event types: vault_created, chamber_advanced, gate_cleared, patch_created/submitted/approved/rejected, extraction_complete, etc.

GAP: Admin actions (invites, role changes, settings) not captured.

Tom's Day 1: "I can see the review queue and approve individual patches, which is solid. But I can't formally approve a vault for Ship — there's no approval artifact, no evidence bundle, and the business rules exist in code but aren't enforced. I wouldn't sign off on a real contract this way."
👑

Sarah — Owner

Ship chamber + Admin Overlay · Publishes, manages workspace, oversees all modules
Ship Chamber
Missing ▶

EXISTS: "Advance to Ship" button works in vault detail. Chamber state stored in DB.

MISSING: No /contracts/ship view. No finalization workflow. No final owner sign-off. No archive/handoff mechanism. No shipped-items metrics. The Ship chamber is a state with no UI.

Dispatch Overview
Partial ▶

EXISTS: Real vault counts per chamber. Recent events timeline. Chamber distribution chart. Quick Compose button. First-upload UX.

MISSING: Signals panel uses hardcoded mock data. Pipeline chart hardcoded. No CRM/Tasks/Calendar KPIs. No cross-module analytics.

User & Workspace Management
Partial ▶

EXISTS: Invite API with 7-day tokens, email sending, accept via OAuth, org_role assignment, members page, role hierarchy enforcement.

CRITICAL: Invites stored in Python dict, not database — restart = data loss. No post-join role editing. No user deactivation. No module-specific roles. No bulk invite. No rate limiting.

Admin Overlay
80% Nonfunctional ▶

EXISTS: 25 admin routes (members, audit-log, roles, workspace, modules, workflows, playbooks, recipes, skills, otto, ai-provider, connectors, features, event-bus, constellation).

MISSING: Config components render but don't save to database. Admin actions not logged. No workspace health/stats dashboard. No seat limits. No billing integration. All *Config.tsx files are UI shells with no backend persistence.

Persistent Settings
Missing ▶

NOTHING PERSISTS: Gate criteria, extraction templates, Otto behavior, module enable/disable, workspace settings, email config, notification preferences, vault archival policy — all missing. Config UI exists but doesn't save.

Notifications
Partial ▶

EXISTS: Real-time push via WebSocket, event categorization, notification types (success/warning/info), unread count.

MISSING: No alert rules ("notify when health_score < 50"). No email notifications. No preferences. No @mentions. No digest/batching.

Sarah's Day 1: "I can see the dashboard and invite team members, which is a start. But I can't ship contracts (no Ship UI), my admin settings don't save (restart = reset), invites are in memory (restart = gone), and there's no way to see cross-module health. Good for a demo, not for running a team."
🤖

Otto — AI Assistant

Embedded copilot · Chat, extraction, tools, gen-ui, persona routing
Chat Interface
Works ▶

EXISTS: Otto chat drawer with vault-scoped and general modes. SSE streaming with abort support. Session persistence, message history. Admin configuration page. Provider switching (Anthropic, OpenRouter). Circuit breaker for reliability.

Users can invoke Otto from any vault and get streaming responses.

SSE Backend
Works ▶

EXISTS: FastAPI SSE streaming, PydanticAI agent integration, graceful fallback chain (API key → agent → stub response), circuit breaker (trips after 5 errors/60s, recovers after 300s). Word-by-word streaming. Token count reporting.

Tool Execution
Framework Only ▶

EXISTS: Tool definitions (get_gate_status, get_field_summary, get_contract_health, search_vaults, suggest_patch, etc.). PermittedTool authorization framework. Risk tier classification. 8 tool-calls-per-message budget.

MISSING: No tool implementations — definitions exist but functions don't execute. PydanticAI agent doesn't call tool executors. Tool results can't be consumed into responses. Risk tier enforcement not active.

Otto can talk about vaults but can't actually query or modify them via tools.

Messenger Integration
Works ▶

EXISTS: Otto can send messages to conversations (authorId = "otto"). SSE-to-WebSocket bridge. Typing indicators during generation. DM deduplication. Reactions, read receipts, GIF picker.

Document Extraction
Works ▶

EXISTS: Six extractors (boolean, split, picklist, date, pattern, text/LLM). Confidence scoring. Metrics tracking. Field normalization. Per-field enable flags.

GAP: Otto receives extraction metadata in context but cannot trigger extraction on demand (no run_extraction tool implemented).

Gen-UI Components
Missing ▶

MISSING: No gen-ui schema integration in Otto routes. No rich component renderer in chat UI. Otto can't generate interactive embeds, forms, gate decisions, or progress trackers. Responses are plain text only.

Gen-UI schemas exist in airlock-gen-ui/configs/ (7 embeds, 5 components, routing config) but aren't wired to the streaming pipeline.

Persona Routing
Structure Only ▶

EXISTS: PersonaContext dataclass, persona injection into system prompt, warm-start context block, DECF profile fields.

MISSING: Persona service integration (OTTO_STATE_SERVICE_URL) not connected. No actual persona routing on session init. Session count always 0. No team dynamics.

Proactive Notifications
Missing ▶

MISSING: Otto cannot create notifications, proactively alert users, push signals to Dispatch, or generate Triage items. Otto is fully reactive — user asks, Otto answers. No background processing.

Otto's Day 1: "I can chat with users and stream responses. I know about their vaults from enrichment context. But I can't do anything — no tool calls, no rich UI, no proactive help. I'm a chatbot when I should be a copilot."

Build-Out Plan: From Alpha to Human-Ready

Prioritized by what unblocks the most users across all roles. Each sprint delivers a complete vertical slice — not just backend or frontend, but the full user workflow.

Sprint 1 Unblock the Core Loop 5 days · Unblocks: Builder + Gatekeeper
  • P0 Build Chamber — Field Editing UI: Create editable field form (inline edit + edit drawer). Wire RecordInspector to patch store. Create → submit → track patches from the vault detail view. Builder
  • P0 Vault Approval Model: Create vault.approvals JSONB model. Block review→ship until Gatekeeper + Owner approve. Call check_review_to_ship() in advance_chamber route. Log approval artifacts as events. Gatekeeper
  • P0 Messenger UI Surface: Add chat drawer to shell layout. Wire ConversationList + ChatView to messenger store. Connect to WebSocket for real-time delivery. Show unread count badge. All
  • P0 Migrate Invites to Database: Move from in-memory dict to invites table. Add Alembic migration. Add invite revocation and post-join role editing. Owner
Sprint 2 Complete the Lifecycle 5 days · Unblocks: Owner + Otto
  • P0 Ship Chamber View: Create /contracts/ship page with finalization checklist, owner sign-off, archive/handoff actions. Display shipped vault metrics on Dispatch. Owner
  • P1 Evidence Pack View: Bundle documents + extractions + patches into a single review surface. Show completeness status. Enable Gatekeeper certification stamp. Gatekeeper
  • P1 Otto Tool Implementations: Wire 4 read tools (get_gate_status, get_field_summary, get_contract_health, search_vaults). Add tool execution handler in PydanticAI agent. Add suggest_patch as first write tool. Otto
  • P1 Admin Settings Persistence: Create workspace_settings table. Wire config components to save/load via API. Add admin audit logging for setting changes. Owner
Sprint 3 Connect the Ecosystem 5 days · Makes modules useful together
  • P1 Dispatch → Real Data: Replace all mock data (signals, queue, feed) with real API queries. Wire Triage Signals widget. Add cross-module KPIs. All
  • P1 Triage ↔ Vault Integration: Create tasks from vault context. Link tasks to vaults bidirectionally. Auto-create tasks on gate failure. Show related tasks in vault Triptych. Builder
  • P1 Gate Response Routes: Implement vault-level gate pass/fail/override endpoints. Wire ApprovalGate component. Add gate criteria configuration in Admin. Gatekeeper
  • P2 Gen-UI Pipeline: Wire gen-ui schemas to Otto's streaming response. Add component renderer in chat UI. Start with 2 embeds (confidence_heatmap, gate_decision) and 1 component (action_buttons). Otto
Sprint 4 Polish & Confidence 5 days · Makes it feel production-ready
  • P2 CRM Completion: Build contacts + deals views using vault hierarchy. Entity linking. Activity timeline. Merge duplicate entities. Builder + Owner
  • P2 Document Library: Full-text search across uploaded documents. Folder hierarchy. Tagging. Link documents to vaults visually. Builder
  • P2 Otto Persona Service: Connect OTTO_STATE_SERVICE_URL. Load persona data on session init. Route system prompt by chamber + user archetype. Track session counts. Otto
  • P2 Email Notifications: Alert rules engine. Email delivery via Resend. Notification preferences in admin. @mention support in chat. All
