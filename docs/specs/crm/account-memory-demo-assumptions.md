# Account Memory Demo Assumptions

## Purpose

Record what the first demo expression of account memory is intended to communicate and what it does not commit the product to.

## Demo communicates

- mixed channel history in one account context
- stakeholder-aware composition
- routing and approval states
- AI suggestions and memory linkage
- documents, meetings, and tasks tied into one narrative

## Demo does not commit to

- real provider delivery
- true inbox sync
- email thread fidelity
- telephony backend
- automatic identity resolution correctness
- final information architecture
- permanent use of the word Vortex in production UI

## Demo defaults

- CRM account detail is the primary home
- Messenger patterns are reused as UI primitives
- Vortex is a secondary concept label only
