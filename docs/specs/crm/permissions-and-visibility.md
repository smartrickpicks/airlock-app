# Permissions and Visibility

## Purpose

Define the minimum permission and visibility rules required for account-memory planning and demo behavior.

## Capability classes

- view thread
- view internal notes
- compose external draft
- send external communication
- target stakeholder groups
- approve outbound communication
- invoke AI draft assist
- manage routing

## Visibility classes

- internal only
- external draft
- external sent
- system event

## Required planning rules

- internal notes must be clearly separated from customer-visible actions
- users may draft without being allowed to send
- channel access may differ by role
- stakeholder-group targeting may be limited by account ownership or permissions
- approvals must be explicit and attributable

## Demo requirement

The demo should show at least:

- one internal-only note
- one pending email approval
- one text draft blocked behind approval
