# Event Bus (BullMQ) Admin UI — Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build the frontend admin monitoring UI for the BullMQ event bus — queue health cards, event flow visualization, DLQ management table, and job detail views — all driven by mock data.

**Architecture:** New admin tab at `/admin/event-bus` within the existing admin overlay infrastructure. Mock data models the 6 queues from the EventBus spec (crm-events, tasks-events, calendar-events, notifications-events, admin-events, analytics-events), 22 event types, job lifecycle states, and DLQ entries. Zustand store for state management with the standard apiFetch-try/mock-catch pattern.

**Tech Stack:** Next.js 14 App Router, TypeScript, Zustand, Tailwind CSS tokens, Lucide icons

```typescript
// ─── Types ───────────────────────────────────────────────────────────

export type QueueName =
  | "crm-events"
  | "tasks-events"
  | "calendar-events"
  | "notifications-events"
  | "admin-events"
  | "analytics-events";

export type JobStatus =
  | "waiting"
  | "active"
  | "completed"
  | "failed"
  | "delayed";

export type EventType =
  | "contract.shipped"
  | "contract.failed"
  | "entity.resolved"
  | "entity.new_customer"
  | "extraction.completed"
  | "health.updated"
  | "gate.advanced"
  | "patch.submitted"
  | "patch.approved"
  | "batch.completed"
  | "batch.failed"
  | "account.created"
  | "account.health_changed"
  | "task.created"
  | "task.overdue"
  | "sla.warning"
  | "sla.breached"
  | "feature.circuit_breaker";

export interface QueueStats {
  name: QueueName;
  pending: number;
  active: number;
  completed: number; // last hour
  failed: number; // last hour
  dlqSize: number;
  avgDurationMs: number;
  concurrency: number;
}

export interface EventBusJob {
  id: string;
  queueName: QueueName;
  eventType: EventType;
  status: JobStatus;
  sourceModule: string;
  sourceVaultId: string;
  workspaceId: string;
  payload: Record<string, unknown>;
  attempts: number;
  maxAttempts: number;
  createdAt: string;
  processedAt: string | null;
  failedAt: string | null;
  duration: number | null; // ms
  error: string | null;
}

export interface DLQEntry {
  id: string;
  queueName: QueueName;
  jobId: string;
  eventType: EventType;
  sourceVaultId: string;
  errorMessage: string;
  retryCount: number;
  failedAt: string;
  payloadPreview: string; // truncated JSON, first 200 chars
}

export interface EventFlowPoint {
  timestamp: string; // ISO 8601, 1-minute buckets
  processed: number;
  failed: number;
}

export interface CrossModuleRoute {
  eventType: EventType;
  sourceModule: string;
  targetQueues: QueueName[];
}
```

**Mock data constants to create:**

- `QUEUE_CONCURRENCY_CONFIG` — map of queue name to default concurrency (from spec: crm=5, tasks=10, calendar=5, notifications=20, admin=3, analytics=3)
- `MOCK_QUEUE_STATS` — 6 QueueStats objects with realistic numbers (e.g., notifications has highest throughput)
- `MOCK_RECENT_JOBS` — 20 EventBusJob objects across all queues/statuses, with realistic event types and timestamps from the last hour
- `MOCK_DLQ_ENTRIES` — 5 DLQEntry objects with realistic error messages (timeout, handler crash, workspace violation)
- `MOCK_EVENT_FLOW` — 30 EventFlowPoint objects (last 30 minutes, 1-min intervals) with varying processed/failed counts
- `EVENT_ROUTES` — the full routing table from the spec (maps event types to target queues)
- `QUEUE_STATUS_CONFIG` — color/label config for queue health states (healthy=green, degraded=yellow, critical=red) based on DLQ rate thresholds
- `JOB_STATUS_CONFIG` — color/label config for job statuses (waiting=muted, active=primary, completed=success, failed=error, delayed=warning)

### Task 2: Event Bus Zustand Store

**Files:**

- Create: `apps/web/src/stores/event-bus.store.ts`

**What to build:**

Zustand store for event bus admin state:

```typescript
interface EventBusState {
  // Data
  queueStats: QueueStats[];
  recentJobs: EventBusJob[];
  dlqEntries: DLQEntry[];
  eventFlow: EventFlowPoint[];

  // UI state
  isLoading: boolean;
  selectedQueue: QueueName | null;
  selectedJob: EventBusJob | null;

  // Actions
  fetchEventBus: () => Promise<void>;
  selectQueue: (queue: QueueName | null) => void;
  selectJob: (job: EventBusJob | null) => void;
  retryDLQJob: (entryId: string) => void;
  retryAllDLQ: (queueName: QueueName) => void;
  purgeDLQ: (queueName: QueueName) => void;

  // Derived
  filteredJobs: () => EventBusJob[];
  queueHealth: (queue: QueueStats) => "healthy" | "degraded" | "critical";
  totalEventsPerSecond: () => number;
}
```

**Implementation details:**

- `fetchEventBus()` — try apiFetch(`/api/v1/admin/event-bus`), catch → load from MOCK\_\* constants
- `selectQueue(queue)` — sets selectedQueue, clears selectedJob
- `filteredJobs()` — if selectedQueue is set, filter recentJobs by queueName
- `queueHealth(queue)` — returns "critical" if DLQ rate > 1%, "degraded" if > 0.1%, "healthy" otherwise (thresholds from the performance targets spec)
- `retryDLQJob(entryId)` — removes entry from dlqEntries (mock behavior)
- `retryAllDLQ(queueName)` — removes all entries for that queue from dlqEntries
- `purgeDLQ(queueName)` — same as retryAll for mock (removes entries)
- `totalEventsPerSecond()` — sum of all queueStats completed / 3600

**Step 1:** Create the store file.

**Step 2:** Run `pnpm type-check`.

**Step 3:** Commit: `feat(admin): add event bus Zustand store`
