# S3.2 — Notification Preferences: Unified Settings

**Date:** 2026-03-11
**Sprint:** 3

## Problem

NotificationPreferences DB model exists (migration 016) with 8 toggles. ChatPreferences component handles messenger-specific prefs. But there's no unified notification preferences page and no API endpoints to CRUD the preferences.

## Plan

### Task 1: Add notification preferences API endpoints

**File:** `apps/api/src/routes/notifications.py` (modify)

- `GET /api/v1/notifications/preferences` — fetch user's notification prefs (or defaults)
- `PATCH /api/v1/notifications/preferences` — update preferences
- Query NotificationPreferences table, create row with defaults if not found
- Pydantic models: NotificationPreferencesResponse, NotificationPreferencesUpdate

### Task 2: Create NotificationSettings organism

**File:** `apps/web/src/components/organisms/NotificationSettings.tsx`

- Unified notification preferences panel (not just chat-specific)
- Sections:
  - Toast Notifications: master toggle, per-category toggles (contracts, tasks, crm, calendar, docs)
  - Sound: enable toggle, sound selection
  - Email Digest: daily/weekly/off selector
- Fetches current prefs from API, PATCH on change
- Mock fallback with local state

### Task 3: Add NotificationSettings to admin settings page

**File:** `apps/web/src/app/(shell)/admin/settings/page.tsx` (modify)

- Add a "Notifications" section alongside existing Appearance settings
- Render NotificationSettings component
