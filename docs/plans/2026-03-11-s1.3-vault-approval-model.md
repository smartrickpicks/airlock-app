# S1.3 — Vault Approval Model: Enforce Gate Rules

**Date:** 2026-03-11
**Sprint:** 1 (Readiness Audit)

## Problem

`chamber_rules.py` defines transition validators (`check_discover_to_build`, `check_build_to_review`, `check_review_to_ship`) but `advance_chamber_route` in `routes/vaults.py` **never calls them**. Any user with the right role can advance a vault regardless of gate requirements. The Review→Ship transition should require gatekeeper + owner approval, but no approval endpoints exist.

## Current State

- `chamber_rules.py`: 3 rule functions exist, return `(bool, list[str])` tuples
- `routes/vaults.py` line ~221: `advance_chamber_route` only checks `check_chamber_advance_permission()` (role check), then calls `advance_chamber()` directly
- No `/approve` endpoint exists
- Frontend "Advance" button works unconditionally
- Vault metadata has `approvals` field structure expected by rules but never populated

## Plan

### Task 1: Create approval service

**File:** `apps/api/src/services/approval_service.py`

- `record_approval(db, vault_id, user_id, role, workspace_id) → dict`
  - Validates user has correct role (gatekeeper or owner)
  - Stores approval in vault metadata: `metadata.approvals.{role}_approved = True`, `{role}_approved_by`, `{role}_approved_at`
  - Returns updated approval state
- `get_approval_state(db, vault_id, workspace_id) → dict`
  - Returns current approval status from vault metadata
- `reset_approvals(db, vault_id, workspace_id)`
  - Clears approval fields (called when vault moves backward or patch is applied)

### Task 2: Wire chamber rules into advance route

**File:** `apps/api/src/routes/vaults.py` (modify)

- Import `check_discover_to_build`, `check_build_to_review`, `check_review_to_ship` from `chamber_rules`
- Before calling `advance_chamber()`, run the appropriate rule check based on current→next transition
- If rules fail, return 422 with the list of unmet requirements
- Keep existing role permission check as first guard

### Task 3: Add approval endpoints

**File:** `apps/api/src/routes/vaults.py` (modify)

- `POST /api/v3/vaults/{vault_id}/approve` — record approval for current user's role
- `GET /api/v3/vaults/{vault_id}/approvals` — get current approval state
- Pydantic models: `ApprovalResponse`, `ApprovalState`

### Task 4: Frontend approval UI in VaultDetailPage

**File:** `apps/web/src/app/(shell)/(modules)/contracts/[vaultId]/page.tsx` (modify)

- When chamber is `review`: show approval status panel
  - Gatekeeper approved? ✓/✗
  - Owner approved? ✓/✗
  - "Approve" button (only for users with matching role)
- When advancing from review: if rules unmet, show the specific requirements
- Disable "Advance" button until all approvals are recorded

### Task 5: Add approval actions to vault store

**File:** `apps/web/src/stores/vault.store.ts` (modify)

- `approveVault(vaultId)` — POST to approval endpoint
- `fetchApprovals(vaultId)` — GET approval state
- `approvalState` in store state
- Mock fallback for both
