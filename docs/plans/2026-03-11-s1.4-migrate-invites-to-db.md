# S1.4 — Migrate Invites to Database

**Date:** 2026-03-11
**Sprint:** 1 (Readiness Audit)

## Problem

`routes/invites.py` uses `_invites: dict[str, dict] = {}` — an in-memory Python dict. Invites are lost on every server restart. This blocks any real invite workflow.

## Current State

- `_invites` dict in `routes/invites.py` — volatile, no persistence
- Routes: `POST /invite` (create), `GET /invite/{code}/validate` (check), `POST /invite/{code}/accept` (redeem)
- Accept route calls `authenticate_google_user()` for real OAuth
- No SQLAlchemy model exists for invites
- No Alembic migration for invites table

## Plan

### Task 1: Create Invite model

**File:** `apps/api/src/models/invite.py`

SQLAlchemy model + Pydantic schemas:

```python
class Invite(Base):
    __tablename__ = "invites"
    id: str              # ULID PK
    workspace_id: str    # FK, for RLS
    code: str            # unique invite code (UNIQUE index)
    email: str           # invited email
    role: str            # org_role to assign
    module_roles: dict   # JSONB — per-module roles
    invited_by: str      # user_id of inviter
    accepted_by: str     # user_id who accepted (NULL until accepted)
    accepted_at: datetime # NULL until accepted
    expires_at: datetime  # invite expiration
    created_at: datetime
    updated_at: datetime
    deleted_at: datetime  # soft delete
    metadata: dict       # JSONB
```

Pydantic: `InviteCreate`, `InviteResponse`, `InviteValidateResponse`

### Task 2: Create invite service

**File:** `apps/api/src/services/invite_service.py`

- `create_invite(db, workspace_id, email, role, module_roles, invited_by, expires_hours=72) → Invite`
  - Generates ULID + unique code
  - Stores in DB
- `validate_invite(db, code) → Invite | None`
  - Checks code exists, not expired, not accepted, not deleted
- `accept_invite(db, code, user_id) → Invite`
  - Marks accepted_by, accepted_at
  - Returns updated invite
- `list_workspace_invites(db, workspace_id) → list[Invite]`
  - For admin views

### Task 3: Rewrite invite routes to use service + DB

**File:** `apps/api/src/routes/invites.py` (rewrite)

- Remove `_invites` dict entirely
- Import and use `invite_service` functions
- Keep same HTTP contract (same URLs, same request/response shapes)
- Add `db: Session = Depends(get_db)` to all endpoints
- Add `user: dict = Depends(get_current_user)` where needed

### Task 4: Create Alembic migration

**File:** `apps/api/src/migrations/versions/xxx_add_invites_table.py`

- CREATE TABLE invites with all columns
- UNIQUE index on `code`
- INDEX on `workspace_id` (for RLS)
- INDEX on `email` (for lookup)
