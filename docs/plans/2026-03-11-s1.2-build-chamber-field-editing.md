# S1.2 — Build Chamber: Field Editing UI

**Date:** 2026-03-11
**Sprint:** 1 (Readiness Audit)
**Blocker Level:** #1

## Problem

The Build chamber has no dedicated view. When a vault is in `build`, the VaultDetailPage renders `RecordInspector` which is **read-only** — fields display extracted values but cannot be edited. Builders need to correct extraction errors, fill missing fields, and create draft patches before advancing to Review.

## Current State

- `VaultDetailPage` renders `RecordInspector` regardless of chamber
- `FieldCard.tsx` — read-only: shows field_name, extracted_value, confidence, evidence
- `patch.store.ts` — full patch state machine exists (createDraft, transitionPatch, canTransition)
- No `EditableFieldCard` or inline editing exists anywhere
- No Build-specific view/page exists

## Plan

### Task 1: Create `EditableFieldCard` molecule

**File:** `apps/web/src/components/molecules/EditableFieldCard.tsx`

- Extends FieldCard concept but with inline edit capability
- Shows field_name, current extracted_value, confidence badge
- Click-to-edit: clicking the value switches to a text input
- Save/cancel buttons appear on edit
- Calls `onFieldEdit(fieldKey, newValue)` callback on save
- Yellow left-border accent (Build chamber color)
- Status: shows "edited" badge if value differs from original

### Task 2: Create `BuildFieldEditor` organism

**File:** `apps/web/src/components/organisms/BuildFieldEditor.tsx`

- Renders all extraction fields as `EditableFieldCard` components
- Tracks local edits in component state (Map of fieldKey → newValue)
- Toolbar: field count, edited count, "Create Draft" button
- "Create Draft" calls `patchStore.createDraft(vaultId, { edits })` with all modified fields
- Shows existing draft patches if any (from `patchStore.patches`)
- Groups fields by section (same as SectionGroup but editable)

### Task 3: Chamber-aware VaultDetailPage

**File:** `apps/web/src/app/(shell)/(modules)/contracts/[vaultId]/page.tsx` (modify)

- Import `BuildFieldEditor`
- Conditionally render based on `selectedVault.chamber`:
  - `discover` → `RecordInspector` (read-only, as now)
  - `build` → `BuildFieldEditor` (editable)
  - `review` / `ship` → `RecordInspector` (read-only, with approval overlay later in S1.3)
- Fetch patches when in build chamber

### Task 4: Wire patch creation to store

**File:** `apps/web/src/stores/patch.store.ts` (minor modify if needed)

- Verify `createDraft` accepts a map of field edits
- Ensure mock fallback creates a proper draft patch object
- Add `editedFields` to draft metadata so Review can show what changed
