# S2.1 — Patch Approval Chain: Gap Assessment

**Date:** 2026-03-11
**Sprint:** 2 (Readiness Audit)

## Status: Already Built (~95%)

The following components already exist and are fully wired:

- `ApprovalChain.tsx` — Vertical timeline with colored dots, expandable steps, SLA timer
- `PatchActions.tsx` — Dynamic action buttons by state (submit, approve, reject, clarify, hold)
- `PatchList.tsx` — Selectable patch cards with state badges
- `ControlPanel.tsx` — 5-tab panel with Approvals tab rendering PatchList + ApprovalChain + PatchActions
- `PatchStateBadge.tsx` — Color-coded state badges
- `SLATimer.tsx` — Circular countdown timer
- `TriptychLayout.tsx` — Gate-lock mode with GovernanceBar
- `patch.store.ts` — Full state machine with 12 states, 20 transitions, self-approval prevention
- `mock-patches.ts` — 4 sample patches in different states
- Backend: `routes/patches.py`, `services/patch.py`, `models/patch.py`

## Remaining Gaps (from spec)

### Task 1: Self-approval UI enforcement

The spec says "Approve button hidden from DOM — not disabled" for self-approval prevention. Check if PatchActions correctly hides (not disables) approve/reject for the patch author.

### Task 2: Evidence scroll requirement

The spec says "all evidence must be scrolled through before Approve enables". Check if ApprovalChain enforces evidence viewing before enabling approve action.

### Task 3: Verify ControlPanel auto-selects Approvals tab in gate-lock mode

TriptychLayout sets gate-lock view state. Verify ControlPanel switches to "Approvals" tab automatically.

## Approach

Read the existing components and verify these 3 gaps. Fix any that are missing.
