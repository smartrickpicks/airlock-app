# M8: Gate UI — Implementation Plan

**Date:** 2026-03-09
**Milestone:** M8 (MAGS Phase 1)
**Location:** `apps/web/src/`

---

## Objective

Build 5 gate type components for inline gate responses in the Orchestrate panel, plus Dispatch gate cards for the Signal panel. These components render gate checkpoints that the DAG engine (M7) produces, allowing gatekeepers to approve/reject/request changes directly in the UI.

---

## Deliverables

### 1. Mock Data — `src/lib/mock-gates.ts`

Types and mock data for gate responses, gate cards, and gate notifications.

```
GateType: "verification" | "approval" | "density" | "decision" | "convergence"
GateAction: "approve" | "reject" | "request_changes"
GateCardData — Signal panel card (vault name, gate type, assignee, SLA, urgency)
GateResponseData — Orchestrate panel response state (approvals, comments, status)
```

Mock constants:

- `MOCK_GATE_CARDS` — 5 cards across different gate types and urgencies
- `MOCK_GATE_RESPONSES` — Response state per gate type

### 2. Gate Type Components — `src/components/organisms/gates/`

Each component is a self-contained gate response widget rendered inline in the Orchestrate panel.

| Component              | Gate Type    | Actions                    | Notes                                     |
| ---------------------- | ------------ | -------------------------- | ----------------------------------------- |
| `VerificationGate.tsx` | verification | Approve / Reject           | Binary check — data/output correct?       |
| `ApprovalGate.tsx`     | approval     | Approve / Reject + comment | Sign-off with mandatory comment on reject |
| `QualityGate.tsx`      | density      | Approve / Request Changes  | Quality threshold check                   |
| `DecisionGate.tsx`     | decision     | Select option              | Option cards — choose a path              |
| `ConvergenceGate.tsx`  | convergence  | Continue                   | Review summary + confirm                  |

Common patterns (all gates):

- `"use client"` directive (all have state)
- Header: gate type icon + label + SLA timer
- Body: type-specific content
- Footer: action buttons using gate color tokens
- `onAction` callback prop for parent integration
- Approval chain progress (who approved, who's pending)
- Comment textarea where applicable

### 3. Dispatch Gate Cards — `src/components/molecules/GateCard.tsx`

Signal panel notification cards showing pending gates across vaults.

- Vault name + chamber badge
- Gate type icon + label
- Assignee avatar + name
- SLA countdown (uses existing `SLATimer` molecule)
- Urgency border color (green/amber/red)
- Click handler to navigate to vault

### 4. Gate Panel — `src/components/organisms/GatePanel.tsx`

Container that renders the appropriate gate type component based on gate config. Used in Orchestrate panel when a vault has a pending gate.
